The safety-critical invariant — **fact-consistency = 1.000 (zero hallucination)** — holds. Persistent misses are abstractive synthesis sentences (e.g. `db-index-tradeoff` 4 factual / 2 verified) where deepseek-chat paraphrases beyond token-overlap range — a genuine weak-model ceiling, not a test artifact.

**Synthesis grounding improvement applied (not floor-lowering)**: ground each section against BOTH the full sources AND the per-source extracted MAP points (the synthesis is literally built from those points → attributing a section to a point's origin is correct provenance). ## Known limitations
1. **W5 synthesis grounding < floor on deepseek-chat (0.779)** — needs a stronger reasoning tier; label min-tier in RELEASE.md before GA (do not enable on weak local models per §4.5E).
2. **W2 rewrite fact-preservation 0.889 on deepseek-chat** — pre-existing margin (W2 shipped before this slice), surfaced again by the now-wired nightly lane.
3. Real-LLM run used DeepSeek-direct `deepseek-chat` (the only key available locally), not the gateway `deepseek-v4-flash`; the gate is provider-agnostic via env so the gateway tier can be substituted in CI.
4. W4 cite inline-anchor marker syntax is `[cite:<id>]` (engine convention); the UI does not yet auto-insert these into drafts (v.next — surfaces existing anchors only).
5. No subprocess E2E for the new endpoints beyond route unit tests + corpora-parse; a `tests/writing_subprocess.rs` real-server E2E (spec §9.1) is a follow-up.
